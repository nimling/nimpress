The schema beside a component page turns into the one place a component is described. It seeds itself from the component types, and from there defaults, enums, descriptions, and mocks are authored by hand.

## The schema file

Each component page carries one `schema.json` or `schema.yml` beside it. The workshop controls, the validation, and the mock selection all read from that file.

1. `nimpress modules update` upserts source changes into the schema: new props, slots, and events are added and changed type shapes refresh on existing members.

2. Authored fields are never overwritten. A member that disappears from the source stays in the file and is flagged so the author decides.

3. In `nimpress dev` the upsert runs on every component change.

4. `data.schema` in page frontmatter layers over the file for a small curation that does not warrant editing it.

## Coaching warnings

Every pass reports what a reader of the library would miss: props without a description, opaque types, and schema members with no counterpart in the source. The warnings print without failing the run.

## Sizing belongs to the story

A story that needs a width or a height owns it in its own markup or in a harness component it wraps itself in. The workshop frame centers whatever the story mounts and scrolls it when it is larger than the frame.

## Control surface

1. Enum options render as chips, and a long list collapses to one line that expands on hover.

2. A default button at the panel header resets every control to its schema default, and one at the events header resets every handler to the logging stub.

3. Filling a value by mock excludes options already present, so a second click lands on a fresh one.

4. Number mocks respect the minimum and maximum the schema declares.

5. The canvas pans on a middle press or a modifier click, and a modifier double click recenters it.

## Decoration only pages

An index file carrying frontmatter and no body decorates its sidebar group without becoming a page of its own. Such a file needs only `sidebar.name`, and content lint judges a page by its body so the file passes.
