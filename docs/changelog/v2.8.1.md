  title: Pin a source package without a second workflow
  description: A source keeps the standard consumer workflow on its version tag, and the receiver waits for the tagged package version before it pins it.

A source that publishes the package its pages render keeps the same consumer workflow as every other source, on its version tag. The receiver waits for the registry to serve the tagged version before it installs it, so the notify may run beside the publish. The `ref` and `sha` inputs 2.8.0 added to `docs-notify` for a notify started after the publish are gone again; the action takes the tag and the commit from the workflow that runs it, as before. See [Pinning the source package](/actions#pinning-the-source-package).
