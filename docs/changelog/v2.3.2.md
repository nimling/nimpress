The API reference stops being a place you only read.

## Download from the header

The header of a `type: openapi` page carries a download control beside the collapse buttons. It opens a menu with one entry per format and hands over the specification named after the source file.

The source format is served exactly as authored. The other one is converted in the browser, so a YAML source downloads as JSON and a JSON source downloads as YAML. The specification file is copied into the build output beside the page, so the download reads the real file instead of a copy carried inside the page payload.

## A specification can be YAML

`spec` on a `type: openapi` page reads YAML as well as JSON, picked from the file extension. Nothing changes for a `.json` spec.

```yaml
---
title: Pastry API
type: openapi
spec: ./pastries.yaml
---
```

The [OpenAPI example](/openapi-example) page renders a small YAML specification with the control in place.
