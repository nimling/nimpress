  title: Export whole folders with a gate
  description: The export header on a folder index publishes the whole folder, and its object form names the gate the pages carry on the site they are published to.

`export` on a folder's `index.md`, the page behind that folder's sidebar entry, now publishes the whole folder. Every page beneath it goes, and so does every file beside those pages, such as a shared `harness.vue` or a harness setup module, so a component workshop arrives on the receiving site whole. A page beneath it that sets `export: false` stays home together with its subfolders. A page marked on its own exports its folder exactly as before.

The header takes an object as well, `export: { target: samna, gate: components }`. The gate is written into the exported copy only. The repo's own site keeps the page ungated, and the receiving site builds it into a guarded bundle and serves it behind its auth provider like any gated page. A page that carries its own `gate` keeps it.

A folder export carries every file in the folder's subtree, a `template/` folder of raw imports included, not only the files beside its pages. A build no longer fails on a component system that has no pages yet: the harness for it is skipped with a line in the log, so a site can declare the systems it will receive before the first sync arrives.

`nimpress export` and the `docs-export` action follow the same rules, and both copy images and other binary files byte for byte. `export` is now a declared frontmatter field. [Publishing a repo's docs to the central site](/actions) shows the consumer workflow of a nimpress repo, whose change guard reads the content root, and the receiver step that runs `docs-export` when the dispatch mode is `export`.
