nimpress ships as a Claude Code plugin, so an agent in any repo drives the cli through tools instead of a skill copied into place. See [plugin](/usage/plugin).

## The plugin

The nimpress repo is a plugin marketplace. The plugin carries the nimpress skill and starts the nimpress mcp server in the project.

```bash
nimpress plugin put
nimpress plugin put --project
```

`put` adds the `nimling/nimpress` marketplace and installs the `nimpress` plugin, for the user or, with `--project`, in the project settings so everyone who opens the repo is offered it. `nimpress skill` stays for installing the skill alone.

## A tool per command

`nimpress mcp` serves every command as a tool over the model context protocol.

1. Tools are named after the command, `lint`, `build`, `modules_update`, `export`, `guard_map`.

2. Each tool takes `args` for positional arguments, `flags` by flag name, and `cwd` for a site below the project root.

3. `dev`, `view`, and `modules_dev` keep running and return their pid with the first output, and `stop` ends them.

4. The server runs the `nimpress` the repo installs, so the tools match the pinned version.
