A database page reads like a page, and the diagram it carries is navigable.

## The page opens with a band

A `type: dbml` page now starts with a hero band holding the title, the description, the markdown body, and the page buttons, all inside the same centered column every other page uses. Only the diagram is full width. `data` shapes the band: `eyebrow`, `lead`, `logo`, `banner`, and `align`.

| Field | Effect |
|---|---|
| `data.download` | Label on the button handing over the schema source, `false` removes it |
| `data.fullscreen` | Label on the button opening the diagram fullscreen, `false` removes it |
| `data.actions` | Extra links, each with `text`, `link`, and a `variant` |
| `data.height` | Diagram height, the viewport under the site header by default |

The diagram itself runs edge to edge with no padding and no rounded corners, filling the space below the header when the reader scrolls to it.

## Columns are clickable

A column with a foreign key centers the table it points at and selects it. A markdown link written in a column note overrides that: a target naming a table centers that table, and any other target is a page link. The label renders as a pill on the row and the rest of the note stays as the hover title.

That is how a `jsonb` column documents its payload. Draw the payload as a table of its own and link the column at it.

```dbml
Table booking {
  id uuid [pk]
  answers jsonb [note: 'Answers to the booking form, shaped by [booking_answers](booking_answers)']
}

Table booking_answers {
  question_id uuid [not null]
  answer text [not null]
  Note: 'The shape inside booking.answers. No table of its own in Postgres.'
}
```

## Cards never overlap

Connected tables are laid out in columns by distance from the busiest table in their group, card heights are measured from the text they actually carry, and a final pass separates any two cards that would touch. A schema lands readable on first paint.

## A site can live in a subfolder

The new `base` config field states the url prefix a site is served under. Routes, sidebar links, markdown links and images, search results, feeds, canonical urls, the sitemap, guarded bundles, and component harnesses all resolve under it, so a site deploys to a project page or any subfolder without a rewrite in front of it.
