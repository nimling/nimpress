The frontmatter grows two fields that shape how a page sits in the shell.

## Hide and status

One list hides any element of the page chrome, and one word marks the page in the sidebar.

`hide` takes a list of element names. `navigation` drops the sidebar column and the menu button, `toc` the right rail, `path` the breadcrumbs, `footer` the page footer line, and `tags` the tag row. A `hide` list in `defaultFrontmatter` merges with the page's own list instead of replacing it.

```yaml
hide: [navigation, toc]
```

**breaking** The boolean field that hid the right rail is gone. Every page that carried it writes `hide: [toc]` instead, and lint fails on a page that still carries the boolean.

`status` assigns the page a status shown in the navigation sidebar. The row carries a `np-sidebar-status` mark with the status label as its title, and `np-sidebar-status-<identifier>` beside it for coloring.

```yaml
status: new
```

| Identifier | Label |
|------------|-------|
| `new` | Recently added |
| `deprecated` | Deprecated |

The `status` field in `nimpress.config` maps further identifiers to labels, `status: { beta: 'Beta' }`.

## Thirteen callouts

The callout set grows from five to thirteen, and every callout gains a collapsible form and an inline form.

Eight new containers join `tip`, `note`, `warning`, `info`, and `check`: `abstract`, `success`, `question`, `failure`, `danger`, `bug`, `example`, and `quote`. Each carries its own icon and a color pair in light and dark. The title row shows the type name in sentence case, text after the type name replaces it, and `""` removes the row.

```md
:::question Where does the schema live
Beside the page, in the schema file.
:::
```

A JSON payload on the opening line shapes the callout. `collapsible` renders it as a details element that starts closed, `open` starts it expanded, and `inline` set to `start` or `end` floats it beside the block that follows on wide viewports. A custom title and a payload sit together on the line.

```md
:::tip Custom title {"collapsible":true,"open":true}
Content here.
:::
```

| Field | Effect |
|---|---|
| `collapsible` | Renders a details element that starts closed |
| `open` | Starts a collapsible callout expanded |
| `inline` | Floats the callout to the `start` or `end` side of the block that follows |

Callouts nest, with the outer one opened and closed by four colons. The `Callout` component export takes the same `type`, `title`, `collapsible`, `open`, and `inline` as props.

## Content tabs

Any content groups under tabs, and tabs with the same label switch together across the site.

`:::tabs` opens a group, and a `::tab` line followed by the label opens each tab inside it. A tab holds any markdown, including callouts, lists, tables, fences, and another tab group, with the outer group opening and closing on four colons when a tab holds a three colon block. `:::code-group` keeps its shape and renders through the same component, with the panels stripped of padding so the code sits edge to edge.

```md
:::tabs
::tab Python

Install with `pip`.

::tab Go

Install with `go get`.
:::
```

Every tab carries an anchor built from its label, so a link to `#tab-python` selects that tab on load and on click, and the arrow keys move between the tabs of a focused group.

The `tabs` field in `nimpress.config` links every group on the site by label, `tabs: { linked: true }`. Clicking `Python` in one group selects `Python` in every group that carries that label, on the same page and on every later page, remembered in the browser. A `{"linked":true}` payload on one `:::tabs` line links that group alone. The `Tabs` component export takes `tabs`, `linked`, `code`, and a `panel` snippet.

## Code block options

The info line of a code fence takes a JSON object after the language, the way a `dbml` fence already does, and four fields shape the block.

````md
```ts {"title":"main.ts","lines":true,"start":10,"highlight":"2-3,5"}
```
````

| Field | Effect |
|---|---|
| `title` | Renders in the block header in place of the language label, with the language as a small tag at the right |
| `lines` | Renders a line number column that the copy button leaves out |
| `start` | Sets the first line number and switches the column on |
| `highlight` | Marks the given lines with `np-code-line-highlight`, as numbers and ranges separated by commas |

A comment ending with `(1)` becomes a numbered `np-code-annotation` marker, and the number is looked up in an ordered list written directly after the fence. Clicking the marker opens that list item as a `np-code-annotation-tip` beside it with its markdown, and the list leaves the flow. A `!` after the closing parenthesis strips the comment characters around the marker. Only a comment in the syntax of the fence language counts, so a `(1)` inside a string stays text. The [Code blocks](/examples/code-blocks) example renders every option.

## Announcement bar and footer

The header can show an announcement bar and the footer hosts the copyright notice, links to the previous and next page, and links to your social media profiles.

- `announce` in the config takes `text` as one markdown line, `link` to wrap it, and `dismiss` for a close button that remembers the dismissed text until it changes. The bar leaves the viewport when the reader scrolls past the header and returns at the top.
- `footer` in the config is now an object. `text` is the site wide line every page renders, `copyright` sits beside the social links, `social` lists `icon`, `link`, and `name` per profile with the icon in the same three forms `sidebar.icon` accepts, `navigation` turns on the previous and next page links in sidebar order, and `generator` set to `false` removes the `Built with nimpress` line.
- **breaking**: a string value for `footer` is refused by the config schema. Move the line under `footer.text`.
- `hide` with `footer` removes the previous and next links on that page together with the footer line.

See [Getting started](/getting-started) for the header and footer sections.

## Page actions and feedback

Every doc page can link to its own source in the repository and ask the reader whether it helped.

- `repo` in the config takes `url`, `editUri`, and `actions`. With `actions` set to `edit` and `view`, each doc page renders an edit pencil and a view eye at the top right of the content column, linking to that file in the repository. `url` defaults to the `github` field and `editUri` to `edit/main/<contentDir>/`.
- `feedback` in the config takes a `title` and a list of ratings, each with an `icon`, a `name`, a `data` value, and a markdown `note`. The widget renders under the body, shows the note after a click, and dispatches a `nimpress:feedback` event on `document` with the page path and the rating data. nimpress sends nothing anywhere; the site's client module wires the event to its analytics.
- `hide` takes `feedback` to drop the widget on one page.

See [Getting started](/getting-started) for the repository and feedback sections.

## Formatting and images

Inline formatting and images gain the forms technical writers reach for most.

- `==text==` highlights, `^^text^^` marks an insertion, `~~text~~` a deletion, `H~2~O` renders a subscript, and `x^2^` a superscript.
- `++ctrl+alt+del++` renders keyboard keys, with `ctrl`, `cmd`, `shift`, `enter`, `esc`, and the arrow names drawn as their glyphs.
- `{align=left}` and `{align=right}` on an image float it beside the following paragraphs, an image alone in a paragraph with a title renders as a figure with a caption, every image after the first carries `loading="lazy"`, and a `#only-light` or `#only-dark` hash on the source shows the image in that theme only.
- `{.zoom}` on an image opens it full size in a lightbox on click, and `images.lightbox` in the config does that for every image.

See [Formatting and images](/examples/formatting) for every form rendered.

## Icons and math

Icons by shortcode and formulas by katex land in the prose.

- `:lucide-braces:` inlines any of the lucide icons at build time inside a `np-icon` span that follows the text color, `:rocket:` renders the emoji, and braces after the shortcode carry classes and attributes, `:lucide-heart:{.lg .brand}`. The `icons` config field names a folder of custom svg files that `:name:` resolves in, and the same shortcode works in `sidebar.icon` and the footer `social` icons.
- `$$...$$` on its own lines renders a display formula and `$...$` an inline one, rendered by katex as MathML so no stylesheet and no fonts load. `math: false` in the config turns the syntax off.

See [Icons and math](/examples/icons-math) for every form rendered.

## Full pages

`type: fullpage` renders a landing page under the header alone. The sidebar column, the breadcrumbs, the right rail, and the previous and next links are hidden by the type, and the band plus every section of the markdown body spans the viewport. `data.eyebrow`, `data.logo`, `data.background`, `data.tagline`, `data.lead`, and `data.align` shape the band, and `data.width` set to `content` narrows the body back to the doc column. See [Full pages](/page-types/fullpage) and the [Full page](/examples/fullpage) example.
