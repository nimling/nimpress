One fix, for any project that ships prereleases and keeps a changelog of them.

## Prerelease ordering

Changelog entries sort by `data.version`, and everything after the first dash was being read as zero. A project on `1.0.0-alpha0175` had every one of its releases compare as equal, so the collection rendered in whatever order the files happened to arrive in, and the sidebar version list matched.

Version comparison now follows the shape of a semantic version.

| Comparison | Result |
|------------|--------|
| `1.10.0` against `1.2.9` | `1.10.0` is newer, unchanged |
| `1.0.0` against `1.0.0-alpha0175` | the release outranks its own prerelease |
| `1.0.0-alpha0175` against `1.0.0-alpha0099` | compared as numbers, `0175` is newer |
| `1.0.0-rc.10` against `1.0.0-rc.2` | compared as numbers, `10` is newer |
| `1.4.2+build.7` against `1.4.2` | build metadata is ignored, they are equal |

A prerelease identifier is compared left to right, and a run of digits inside one is compared as a number rather than as text, so a zero padded counter like `alpha0099` and an unpadded one like `alpha99` both order the way you would expect.

Nothing changes for a project that only ships plain releases.
