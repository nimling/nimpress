One new frontmatter field, so a docs site can point at a neighbouring site from its own sidebar.

## `link` in frontmatter

A markdown file whose frontmatter carries `link` with an absolute url becomes a sidebar entry that opens that url. It is not a new kind of entry and not a new config block: the file sits in the content tree like any other page, and its position, label, order, icon, and style come from the same fields they always did.

```yaml
---
title: Samna docs
link: https://developer.samna.io
order: 90
sidebar:
  icon: /assets/samna.svg
---
```

The file carries no body. It produces no route, no search entry, and nothing in the build output, the same way a decoration only page already did.

The rendered entry opens in a new tab with `rel="noreferrer"`, carries an outbound glyph, and never highlights as the active route. Put the file at the content root for a top level entry, or inside a folder to place it in that group. On a folder `index.md` the group header itself becomes outbound while its children stay internal.

`nimpress lint` rejects a relative value and rejects a body on a link page.

`redirect` is unchanged and stays the internal counterpart, routing into a page on this site and sending the visitor to another path on this site.
