The component workshop serves each design system from its own dev server, and that server had no command route, so a story calling `postCommand` was refused while a page could run the same command. The harness dev server now answers `/__nimpress/command` with the same `commands.allow` as the site.

## An unguarded command fails the build

A `postCommand` call that is not behind `commandsEnabled` used to build and fail at runtime on the published page. `nimpress build` and the component build now stop with `postCommand reaches the static build from <files>`, naming the modules that import it, so every command call and the ui that triggers it has to sit behind the guard. See [Commands in a static build](/usage/dev#commands-in-a-static-build).
