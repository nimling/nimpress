[D2](https://d2lang.com) is a declarative language that turns text into diagrams. A diagram is a set of shapes and the connections between them, nested into containers as deep as the system goes. nimpress reads D2 itself: the plugin parses and lays out every diagram at build time, and the page draws it from the theme tokens, so the browser downloads no diagram library and the diagram follows the theme toggle with no redraw.

## Usage

### Draw a diagram in a fence

A ` ```d2 ` fence is all a diagram needs.

````md
```d2
direction: right
user: Reader {shape: person}
site: Docs site {
  search -> page
}
user -> site.search: asks
```
````

The diagram renders in the same frame as a mermaid diagram: drag to pan, scroll to zoom, the toolbar resets the view and opens it fullscreen. The frame takes the proportions of the diagram.

### Link a .d2 file

A line holding only an image link to a `.d2` file renders that file as a diagram. The path resolves against the markdown file, or against the content folder when it starts with `/`. The alt text becomes the accessible label of the diagram.

```md
![Platform overview](./platform.d2)
```

Keep a large diagram in its own file. The file renders on the page, sits in the build output beside it, and the dev server redraws the page when it changes.

### Import shared parts

`x: @file` fills the shape `x` with the contents of `file.d2`, and `...@file` spreads them into the current scope. Imports resolve against the file that holds them, so a fence imports beside its markdown file. A linked file or an import that changes redraws the page in dev.

## What the renderer reads

1. Shapes with labels, the `shape` keyword, and nested containers through blocks or dotted keys like `cloud.api`.

2. Connections written `->`, `<-`, `<->`, and `--`, chained as `a -> b -> c`, with a label, a block, and `(a -> b)[0]` references.

3. Every built in shape: `rectangle`, `square`, `page`, `parallelogram`, `document`, `cylinder`, `queue`, `package`, `step`, `callout`, `stored_data`, `person`, `diamond`, `oval`, `circle`, `hexagon`, `cloud`, `text`, `code`, `image`, `sql_table`, and `class`.

4. The children of a `sql_table` or a `class` as its rows, with `constraint` rendered as `PK`, `FK`, or `UNQ`. A connection to a row starts or ends on that row.

5. `direction` on the diagram or on any container, `grid-rows`, `grid-columns`, and the grid gaps, and `near` with a constant such as `top-center` for a title.

6. `style` fields: `fill`, `stroke`, `stroke-width`, `stroke-dash`, `border-radius`, `opacity`, `font-color`, `font-size`, `bold`, `italic`, `underline`, `shadow`, `multiple`, `double-border`, and `animated`.

7. `source-arrowhead` and `target-arrowhead` with the shapes `triangle`, `arrow`, `diamond`, `circle`, `box`, `cross`, and the crow's foot set, `cf-one`, `cf-many`, `cf-one-required`, `cf-many-required`.

8. `label`, `icon`, `link`, `tooltip`, `width`, `height`, `vars` with `${name}` substitution, `classes` with `class`, block strings written `|md ... |`, comments, and `null` to remove a shape.

`layers`, `scenarios`, and `steps` are read and skipped, so the diagram shows the root board. A syntax error renders in place of the diagram with its file and line, and the dev server prints it too.

## Customization

### Colors

A shape with no `style.fill` takes a tint of `--np-brand`, and nested containers deepen the tint per level. Edges take `--np-text-secondary`. A `style` field in the diagram always wins over the theme.

## Restyling

`D2Block` renders nimpress markup with stable classes. See [Renderers styling](/styling/renderers#d2block).
