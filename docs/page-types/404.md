A `type: 404` page is the not found page of the site. The build writes it as `404.html` at the root of the output beside its own route, so GitHub Pages and every static host that reads that file serve it for an unknown address, and the app routes an unknown path to it without a reload. One page per site; lint refuses a second one.

## Frontmatter

```yaml
---
title: This page does not exist
type: 404
description: The address has no page behind it.
---

The page may have moved, or the link may carry a typo.

:::actions {"align":"center"}
[Go to the start](/){"variant":"primary"}
:::
```

`title` is the heading under the code. The markdown body renders below it, so the action row and the prose are the author's. The page stays out of the sidebar, the search index, the sitemap, and the llms file unless a `sidebar` block places it.

## Where it is served

1. `404.html` at the root of `paths.out` is the copy every static host reads. Without a `type: 404` page the build copies the shell there, so an unknown address still boots the app.

2. The app routes an unknown path to the page in place, so a broken link inside the site lands on it without a reload.

3. The page also answers at its own route, `/404` for a file at `docs/404.md`, which is the address to open while writing it.

## Restyling

The code, the title, and the body carry documented classes. See [Page types styling](/styling/page-types).
