Every page under this section is a full flow with the real files rather than a fragment. Copy a page into your own repo, change the names, and it runs.

| Example | What it walks through |
|---|---|
| [Hero page](/examples/hero) | A landing page with a band, action buttons, and a feature grid |
| [Schema viewer](/examples/schema-viewer) | A database rendered as an interactive diagram from one DBML file |
| [OpenAPI reference](/examples/openapi) | A specification rendered as a reference page with a download control |
| [Mermaid diagrams](/examples/mermaid) | Flowcharts, sequences, and state machines inside a doc page |
| [Component workshop](/examples/components) | A component library presented live, from config to story to schema |
| [Publishing to a central site](/examples/publishing) | Two repos, two workflows, one GitHub App, docs flowing on a version tag |
| [Gated pages](/examples/gating) | A page behind a session, the guarded bundle, and the upload flow |
| [Callouts](/examples/callouts) | Every callout type, a custom and a removed title, a nested, a collapsible, and an inline callout |
| [Content tabs](/examples/tabs) | A code group, a tab group of any content, a callout inside a tab, nested groups, linked groups, and an anchor link |

## How to read them

Each example opens with the file tree it produces, then walks the files in the order you create them. Commands are shown as you would run them from the repo root, and every field the example sets is linked to its reference entry.
